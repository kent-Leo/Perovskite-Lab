# 工作表交互与中西文字体（v1.0.0）

日期：2026-11-05　分支：`feature/v1.0.0`　基础版本：v0.9.5（`103e5c0`）

本轮两件事：把工作表交互补齐到接近 Excel（拖拽自动滚动、连续选区外框、整块复制粘贴、撤销重做与大数据量拖拽），以及把科研绘图字体改成 Word 式的中西文分别设置并保证 SVG / PNG / PDF 一致。

## 一、先确认没有重复开发

动手前按源码而不是文档核对过一遍：

| 需求 | 实际状态 | 本轮处理 |
| --- | --- | --- |
| 矩形拖拽框选 / 越界选择 | 已实现（窗口级 pointermove 命中） | 复用，补自动滚动 |
| Shift 连选、整行整列、全表选择、列标拖动连选 | 已实现 | 复用，随回归测试 |
| TSV 复制粘贴、`pasteWorksheetRange`、只读保护、原子校验 | 已实现 | 修起点、补提示、加测试 |
| 单元格编辑 / 粘贴 / 清空的撤销重做 | 已实现（组件内 history） | 复用，加测试 |
| 插入行 / 列、Sheet 新建 / 重命名 / 删除的撤销 | 未实现 | 评估后保持原状，见「已知限制」 |
| 中西文字体独立设置 | 未实现（只有单一 `fontFamily`） | 新增 |
| SVG / PNG / PDF 字体嵌入 | 已实现（单一字体） | 扩展为中西文双字体 |

## 二、工作表交互

### A1 拖拽自动滚动

`Worksheet-v0.2.0-2026.10.19.tsx` 的拖拽 effect 里新增 `requestAnimationFrame` 循环：

- 指针进入 `.worksheet-scroll` 可视区边缘 26px 内开始滚动，速度按越界距离线性增长（上限 26px/帧），支持水平、垂直与对角线。
- 每帧只改容器的 `scrollTop` / `scrollLeft`（不动整页滚动），随即用最后一次指针位置重新命中单元格并扩展选区，所以滚动时选区会继续长大。
- 到达滚动边界后循环自动退出，不会空转；下一次 `pointermove` 会重新启动，所以「停在边缘不动」不会一直烧 CPU。
- `pointerup` / `pointercancel` / 窗口失焦（指针在窗口外松开）都会立即 `cancelAnimationFrame` 并清空状态，组件卸载时同样清理。
- 容器比窗口高时，触发区按可见窗口收拢，否则底部边缘永远进不了触发区。
- 命中判定从 `elementFromPoint` 改为 `elementsFromPoint`，这样粘性表头、行号列盖住的单元格也能命中，拖到顶部时不会直接失效。

### A2 选区视觉

沿用原有 `is-selected` / `is-active` 状态，新增 `is-range-top|bottom|left|right` 四个边缘类，用 CSS 变量把四边内阴影拼成连续外框，活动单元格的高亮环作为额外一层阴影叠加：

```css
.worksheet td.is-selected,
.worksheet td.is-active {
  box-shadow:
    inset 0 var(--range-top, 0) 0 0 var(--range-color, transparent),
    inset 0 calc(-1 * var(--range-bottom, 0px)) 0 0 var(--range-color, transparent),
    inset var(--range-left, 0) 0 0 0 var(--range-color, transparent),
    inset calc(-1 * var(--range-right, 0px)) 0 0 0 var(--range-color, transparent),
    inset 0 0 0 var(--active-ring, 0) var(--active-color, transparent);
}
```

不做绝对定位覆盖层，边框天然跟着单元格走，滚动、滚轮、换行都不需要额外同步；标红单元格与只读底色规则仍然优先级更高，外观不受影响。

### A3 复制与粘贴

- 粘贴起点统一为**选区左上角**（新增领域函数 `pasteOrigin`），反向框选与正向框选结果一致；单击单元格时左上角就是该单元格。
- 只有在粘贴事件不是来自活动单元格（例如脚本或其它元素派发）时，才用事件所在单元格作为起点，避免误写到别处。
- 工具栏「粘贴」与 ⌘V / Ctrl+V 走同一个 `paste()`；粘贴后选区自动更新为写入的数据块。
- 行数、列数越界分别给出明确提示；类型校验在写入前整块完成，任一处失败就整批不写，只读计算列依旧拒绝覆盖。

### A4 撤销与重做

- 单元格编辑、批量粘贴、Delete 清空：组件内 history（最多 20 步，且按数据量限制内存），⌘Z / Ctrl+Z 撤销，Ctrl+Y 与 ⌘⇧Z / Ctrl+Shift+Z 重做，两个重做快捷键都可用。
- 多探针识别分析：沿用页面级 `externalHistory`，行插入、探针增删与数据修改都能撤销。
- 插入行 / 列、删除行、Sheet 新建 / 重命名 / 删除：**不在本轮撤销范围内**，原因见「已知限制」。

### A5 大数据量

- 选区判定改用渲染前算好的 `bounds` 直接比较，不再对每个单元格调用两次 `cellInSelection`（每次都会重算矩形）。
- `pointerenter` 与窗口 `pointermove` 都改为函数式更新，坐标没变就返回同一个 state 对象，React 不再重渲染。
- 拖拽只更新选区状态，不触碰 `rows` / `columns`，因此不会触发图表重算；工作区状态没变，图表也不会重绘。
- 未引入任何虚拟滚动库，保留原有 `WORKSHEET_LIMITS`（10 万行 / 64 列 / 50 万格 / 20MB）。

### A6 回归覆盖

拖拽框选、Shift 连选、整行整列、全表选择、列标拖动连选、⌘A/C/V、多行多列复制粘贴、Delete、方向键 / Tab / Enter、F2 / 双击编辑、行号拖动排序、多 Sheet、Excel/CSV/TXT 导入都由 `npm run test:browser` 的既有 25 个 spec 覆盖，本轮全部通过。行号在有排序功能的表格里仍是拖拽把手，整行连选只在没有排序回调的表格生效——保持原有安全行为。

## 三、中西文字体

### 数据模型

`ChartStyle` 新增两个**互相独立**的可选字段：

```ts
cjkFontFamily?: string;   // 中文字体；缺省沿用 fontFamily
latinFontFamily?: string; // 西文字体；缺省沿用 fontFamily
```

旧工作区没有这两个字段 → `effectiveFonts()` 判定 `mixed === false`，根节点 `font-family` 与旧版本逐字一致，图表输出不变，因此不存在迁移破坏。

### 混排实现

`src/domain/chart-fonts-2026.11.3.ts` 负责排版规则：

1. 按 Unicode 类别切分运行段：CJK 表意文字 / 扩展区 / 兼容区 / 中日韩标点 / 全角形式走中文字体，其余（英文、数字、希腊字母、数学符号）走西文字体。
2. 只有真正混排的字符串才切 `<tspan font-family>`；纯中文或纯西文仍是一个文本节点，由根节点字体决定，避免无谓的标记膨胀。
3. SVG 根节点字体栈 = 西文回退链 + 中文回退链 + 通用族，缺字自动向下回退（例如 Tinos 缺 `⁺` 时继续找宋体）。
4. 原始字符串不拆分、不改写，运行段只是渲染载体。
5. `text-anchor` 在 Chrome 上是对整段 tspan 求总宽后居中/右对齐，旋转轴标题的 `transform="rotate(...)"` 在外层 `<text>` 上，混排后位置与基线保持正确。
6. 化学式上下标由 `chemicalText()` 生成，现已支持传入样式，嵌套 `<tspan baseline-shift>`，PDF 导出也会读取 `baseline-shift` 与 `font-size` 百分比，不再把上下标压回基线。

图表侧的三个 `text()` 生成点（`chart.ts`、`recognition-charts`、`recognition-paper-charts`）统一改用这套函数，因此荧光光谱、对象筛选、校准曲线、PCA 得分 / 载荷、层次聚类树状图、响应热图、数据点数值与图例全部覆盖。多探针页面里修改任一图表的字体也会同步到同页的评分图与树状图（`setStyle` 的共享字段列表已加入两个新字段）。

### 界面

「图表设置 → 外观」新增：

- 中文字体选择器（宋体 Noto Serif SC / 黑体 Noto Sans SC / 衬线）。
- 西文字体选择器（Times New Roman / Arial / Perovskite Lab Serif / Sans / Song）。
- 预设按钮「宋体 + Times New Roman」，选中状态由 `aria-pressed` 反映。
- 实时混排预览：用与 SVG 完全相同的字体栈渲染 `CsPbBr3 钙钛矿量子点 Intensity (a.u.)`，下方直接写出「中文 X · 西文 Y」与导出实际使用的字体。
- 修改中文不会动西文，修改西文不会动中文；切换上方「字体」等于重设整套排版，避免旧选项被静默忽略。

### 授权

Times New Roman 不复制、不打包、不嵌入。预览优先使用系统已安装的 Times New Roman；PDF 无法读取系统字体文件，因此嵌入度量兼容的 [Tinos](https://github.com/google/fonts/tree/main/ofl/tinos)（SIL OFL 1.1），并在界面文案里明确写出「PDF / SVG 嵌入 Tinos（Times New Roman 的度量兼容开源替代）」，不冒充 Times New Roman。来源、SHA-256 与覆盖字符见 [`public/fonts/字体替代与授权-2026.11.5.md`](../public/fonts/字体替代与授权-2026.11.5.md)。

| 格式 | 结论 |
| --- | --- |

## 八、已知限制

1. **插入行 / 列、删除行、Sheet 新建 / 重命名 / 删除不可撤销。** 这些操作由各页面在 `Worksheet` 之外直接改工作区，行对象带内部 id，仅凭行快照回滚会让对象与列映射错位（例如对象筛选、校准、浓度梯度页）。要支持必须把每个页面的行结构操作收进统一的页面级历史栈，属于状态架构重构，按需求「如存在高风险重构应保持原实现」保留现状。单元格编辑、粘贴、清空与多探针页的行插入仍可撤销。
2. **PDF 中的系统字体无法真实嵌入。** 选择 Times New Roman 时 PDF 使用度量兼容的 Tinos，字形是替代字体（宽度、行高一致，字形细节不同）；界面已明确标注，不声称「完全一致」。
3. **Times New Roman 是否存在取决于系统。** 预览优先用系统字体，缺失时回退 Tinos；两者度量兼容，但肉眼仍可分辨字形差异。
4. **图表边距估算仍用字符数启发式。** `labelWidth` 以「中日韩 1.0 / 西文 0.65 × 字号」估算宽度，中西文字体切换后个别极端长标题可能留白偏多或偏少，不影响导出文字本身。
5. **SVG 体积。** 含中文的图会内嵌宋体（WOFF 约 8.5MB，base64 后约 11MB），这是既有设计；英文图不再内嵌中文大字体，体积明显更小。

## 九、人工验收项目

无法用自动化测试代替的部分：

1. Windows 与 macOS 实机：按住左键拖到表格下方 / 右侧边缘，确认滚动流畅、松手即停；触控板双指滚动与行号拖动排序不受影响。
2. 中文输入法组合输入（拼音未上屏时）不触发快捷键、不打断选区。
3. 装有 Times New Roman 的 Windows / macOS 打开导出的 PDF、SVG，确认西文就是 Times New Roman 字形；未安装的机器确认回退到 Tinos 后版面不跳行。
4. 用 Excel 打开「复制选区」得到的文本、把 Excel 的多行多列粘回工作表，核对行列结构。
5. 在 Word / Adobe Illustrator 中打开导出的 PDF / SVG，确认中文为宋体、西文为 Times New Roman（或 Tinos），上下标未错位。

## 十、后续优化建议

1. 把每页的行结构操作统一收进一个按 sheet 隔离的页面级历史栈，补上插入 / 删除行、Sheet 操作的撤销（需先梳理各页 `onChange` 的 id 映射）。
2. 用真实字体度量替换 `labelWidth` 启发式（浏览器端可用 `CanvasRenderingContext2D.measureText`，导出端可用 `fontkit`），让图边距与刻度标签更贴合。
3. PDF 导出按实际使用字符做字体子集化，替换当前 `subset: false`，可把带中文的 PDF 从约 9MB 降到百 KB 级。
