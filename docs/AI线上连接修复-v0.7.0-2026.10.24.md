# AI 线上连接测试修复（v0.7.0，2026.10.24）

## 问题与原因

线上 `sci.luzen.org` 的“测试连接”返回 HTTP 502，界面提示“AI 请求失败，请检查网络后重试”。使用虚构密钥的诊断请求复现了相同响应，未读取用户密钥，也未产生模型费用。

原转发请求设置 `redirect: "error"`。Cloudflare Workers 未实现该模式，会在构造请求时抛出 TypeError，尚未发出上游请求；原统一异常处理将其误报为网络问题。Node.js 的 fetch 支持该模式，因此此前单元测试和本地打包未发现这一运行时差异。

依据：[Cloudflare Workers Request 文档](https://developers.cloudflare.com/workers/runtime-apis/request/#constructor)。

## 修复

- 转发请求改为 `redirect: "manual"`，兼容 Node.js 与 Cloudflare Workers。
- 对所有 HTTP 3xx 明确停止处理，不跟随重定向，不向新地址转发 Authorization，也不向网页回显 Location。
- 默认 fetch 使用全局对象调用，保留运行时接收对象。
- 将后端出站网络失败、上游非 JSON 响应、运行时异常分开提示，避免全部归为浏览器网络问题。
- 服务商白名单、请求体与响应体上限、超时、个人密钥计费及密钥不进入日志等约束保持不变。

## 验证

- 135 项单元测试通过；新增 Workers 参数约束、3xx 拦截与错误区分验证。
- TypeScript 检查与生产构建通过。
- 使用真实 workerd 2026-10-19（兼容日期 2026-10-19）运行隔离对比测试，六项检查全部通过：旧版处理器在联网前复现相同 502；修复版连接测试与分析请求均通过真实 Request 构造；302、307、308 响应均被拦截且未发出后续请求。隔离测试在本机运行，没有部署临时测试接口。
- 未向服务商发送真实用户密钥；线上诊断仅使用无效的虚构密钥。

## 部署

修复在 `server/ai-handler-2026.10.24.ts`，需要重新部署包含 Worker 入口的版本。仅刷新浏览器或只上传 dist 无法替换线上后端代码。现有域名、个人密钥和浏览器保存方式无需更改。

本记录描述本地修复，不表示线上已更新。
