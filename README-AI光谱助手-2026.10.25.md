# Perovskite Lab · AI 光谱助手（2026.10.25）

分支：`develop/v0.7.0`　｜　新增页面：**AI 光谱助手**　｜　不替换原有光谱工作台

本次升级在现有 React + TypeScript + Vite 项目上新增独立页面，完成从 **F-7100 TXT 上传 → 自动识别异常 → 数值处理 → 前后对比 → 用户确认 → Excel 导出 / 同步到网站 Sheet** 的完整闭环。原有光谱工作台、多 Sheet、对象筛选、校准曲线、浓度梯度、峰特性分析和已有 AI 辅助面板均保留。

## 1. 页面入口与完整流程

侧边栏新增 **AI 光谱助手**（`#assistant`），不需要先进入光谱工作台导入文件。

1. 上传一个或多个 TXT / CSV / TSV；空白光谱可作为另一个文件一起上传。
2. 自动解析编码、分隔符、数据起始行、波长/强度列和 F-7100 元数据，立即绘制原始光谱。
3. 数值算法自动检测孤立异常点、连续异常区间和与激发波长相关的散射候选，同时自动保护主发射峰。
4. 在“原始与处理后光谱”中查看原始曲线、处理后曲线、已修复点、仅标记点和屏蔽区间。
5. 切换左侧模块（如光谱工作台、对象筛选）后再返回，已上传文件、解析结果、对话和未确认结果都会保留；只有刷新页面才会重置 AI 助手会话。
6. 可在对话区输入自然语言指令，指令会转换为可验证的参数或操作，例如：
   - `帮我处理异常尖峰`
   - `只标记不修改`
   - `不要修改主峰附近`
   - `保护 500–540 nm`
   - `重新分析 450–550 nm`
   - `屏蔽散射`
   - `阈值更保守`
   - `显示处理前后的光谱`
   - `确认处理结果` / `导出 Excel` / `同步到 Sheet`
7. 可选的 **AI 辅助分类** 只返回文字分类与建议，不直接修改强度。
8. 点击“确认处理结果”后：
   - 默认自动同步到一个新 Sheet（可在结果操作区关闭自动同步）；
   - 可独立下载四表 Excel；
   - 可更新已同步 Sheet，或创建新版本。

处理参数、原始数据或空白发生变化时，旧确认状态立即失效；必须重新生成并重新确认后才能导出或同步。

## 2. F-7100 TXT 解析

新增独立解析模块 `src/services/f7100-2026.10.25.ts`，保留原通用 TXT/CSV 导入能力。

- 自动识别 UTF-8、GB18030/GBK、UTF-16 LE/BE，并提供 Shift-JIS、Windows-1252 手动选项。
- 自动识别制表符、逗号、分号、竖线和空格分隔。
- 优先定位 `Data points` 段落，读取 `nm / Data` 数据块；`Peaks` 表不会被误当作光谱数据。
- 提取文件实际存在的元数据：样品、文件名、测量日期、仪器型号/序列号、扫描模式、激发波长、发射起止波长、狭缝、PMT、校正状态等。
- 无法识别时给出明确错误，并保留“检查 / 修正识别结果”面板，可手动指定编码、分隔符、首个数据行、波长列和强度列后重新解析。
- 跳过非数值或重复波长的行会显示数量、行号和原因，不会静默丢失。
- **明确拒绝三维 EEM / 3-D scan**，不会抽取某一层冒充一维发射光谱。
- 若文件带 F-7100 元数据但缺少 `Data points`，也会明确拒绝，避免把 `Peaks` 表误读成数据。

## 3. 异常检测与处理算法

模块：`src/domain/assistant-processing-2026.10.25.ts`

算法版本：`assistant-numeric-2026.10.25.1`

### 3.1 孤立异常尖峰

- 使用 Hampel 局部中位数 + MAD 稳健检测，默认窗口 7 点、阈值 4σ。
- 额外使用最大修复跨度之外的锚点复核，避免连续 3–4 点异常被自身填满窗口后漏检。
- 要求异常幅度同时满足稳健 z-score 和相对局部强度阈值，避免把宽谱带内的小噪声当作宇宙射线尖峰。
- 仅当连续异常点数量不超过“最多连续修复 / 点”（默认 3）且左右两侧都有可信测量锚点时，才做局部线性插值。
- 边缘异常、超长连续异常区间不会插值：默认留空屏蔽；也可选择“仅标记、保留原值”。

### 3.2 真实荧光峰保护

- 对平滑谱线检测局部极大值，要求具有足够的半高宽和左右相邻点支撑，孤立单点尖峰不会被当作真实峰。
- 自动保护主发射峰，以及高度达到主峰 10% 以上的次级峰；默认额外边界 2 nm，可调整。
- 用户可设置手动保护区，或通过“不要修改主峰附近 / 保护 500–540 nm”扩大保护。
- 保护区内不做修复、不屏蔽；散射候选与保护区重叠时不会自动屏蔽。

### 3.3 散射干扰

- 根据激发波长计算候选：
  - 瑞利散射：λex
  - 二级瑞利散射：2λex
  - 拉曼散射：水约 3400 cm⁻¹、乙醇/甲醇约 2900 cm⁻¹ 的估算位置
- 候选区间结合半宽、局部峰高、发射狭缝和同条件空白信号提示。
- 默认只标记、不修改；“屏蔽散射”只屏蔽未与目标峰保护区重叠的区间，屏蔽点在处理后数据中留空，原始值仍保留。

### 3.4 空白扣除

- 必须显式选择空白并确认测量条件一致。
- 空白波长范围必须覆盖样品范围；仅在实测范围内线性内插，不外推。
- 保留扣除后的负值，不截断、不平滑代替扣除。

### 3.5 质量检查

每个结果包含：

- 输入/输出行数与波长是否逐点保留；
- 原始强度是否被覆盖；
- 主发射峰是否保留、强度比是否在 0.95–1.05；
- 屏蔽区间是否留空、是否伪造强度；
- 修复/屏蔽/待判断点数量；
- 空白覆盖范围；
- 散射候选与保护区是否重叠。

## 4. Excel 导出（4 张表）

模块：`src/services/assistant-export-2026.10.25.ts`。只有确认后的结果允许导出。

| 工作表 | 内容 |
| --- | --- |
| 原始数据 | 来源文件、源文件行号、序号、波长、原始强度、空白插值、保护状态；原始强度逐行保留 |
| 处理后数据 | 波长、原始强度、空白插值、处理后强度、异常标记、处理状态、处理方法、理由、保护状态；可直接用于 Origin/Excel 绘图 |
| 杂峰处理记录 | 每个受影响点一行：记录号、异常类型、处理状态、区间、波长、原始值、修复值、最大偏离σ、方法、理由、AI 辅助说明 |
| AI 分析报告 | 文件/仪器/测量日期/激发波长/扫描范围/编码/分隔符、全部处理参数、算法版本、结果统计、主峰强度比、质量检查、处理警告、AI 服务商/模型/说明/分类、用户指令 |

导出文件不包含 API Key、Authorization、AI 会话或请求头。所有数值均为可编辑单元格，不使用公式；屏蔽点“处理后强度”为空，不会被伪造。

## 5. 同步到网站 Sheet

模块：`src/services/assistant-sheet-2026.10.25.ts`，复用现有 raw 工作簿模型。

- 默认名称：`原始文件名_AI处理`，同名时自动追加序号；不会覆盖已有 Sheet。
- 新 Sheet 包含：
  - 波长、原始强度、处理后强度、异常标记、处理方法五列；
  - 两条已注册的光谱曲线（原始、AI 处理），自动激活并显示；
  - 列头名称、单位、颜色元数据，可直接继续编辑和绘图。
- 同步后自动切换到该 Sheet；可在“光谱工作台”继续做峰特性分析、复制到对象筛选/校准数据表等。
- 重复同步保护：
  - 相同结果再次确认时，默认按钮变为“更新已同步 Sheet”，只更新原 Sheet；
  - 结果变化后默认创建新版本；
  - 可显式选择“创建新版本”或“更新已同步 Sheet”。
- Excel 与 Sheet 均直接读取同一份 `AssistantProcessingResult`，不经过 Excel 中转，已由单元测试逐行比对。

## 6. AI 服务商、模型与安全

- 保留 DeepSeek / OpenAI 服务商、模型选择、个人 API Key、显示/清除密钥、测试连接。
- 密钥保存在专用浏览器本地存储，按服务商分开；不进入工作区、Excel、日志、GitHub 或请求响应。
- 只有点击“测试 AI 连接”或“AI 辅助分类”才调用模型；需先勾选数据发送与个人账户计费说明。
- 新接口：`POST /api/ai/assistant`，继续由现有 Worker 的 `/api/*` 路由转发。
- 接口只接受白名单服务商/模型、同源 JSON、限长请求；AI 只能返回 `summary / anomalyNotes / recommendations` 文本，不能返回或修改任何强度数值。
- AI 返回的异常编号必须是本地已存在的编号；分类和置信度只接受固定枚举。
- AI 说明会写入 Excel 报告；AI 分析会使旧确认失效，需要重新确认。

## 8. 生产部署（Cloudflare Worker）

本项目同时需要静态资源和 Worker。仅上传 `dist` 不会更新 AI 转发接口。

```sh
npm install
npm test
npm run build
npx wrangler deploy --config wrangler.jsonc
```

`wrangler.jsonc` 已配置：

- `main`：`worker/ai-worker-2026.10.24.ts`
- `assets.directory`：`./dist`
- `assets.run_worker_first`：`["/api/*"]`

部署后验证：

```sh
# 无密钥应返回 401，而不是 404 / 502
curl -i -X POST https://sci.luzen.org/api/ai/assistant \
  -H 'Content-Type: application/json' \
  -H 'Origin: https://sci.luzen.org' \
  --data '{}'
```

然后在页面中填写真实个人 API Key，先“测试 AI 连接”，再执行一次“AI 辅助分类”。本地测试通过不等于生产部署成功；必须用真实域名、真实 Worker 和用户自己的 API 账户确认。

**2026.10.25 本地检查时的线上状态：**

- 不带密钥的 `POST /api/ai/test` 返回 `401 请填写有效的 API Key`，说明旧转发接口可达。
- 使用明确虚构密钥调用 `POST /api/ai/test` 返回 `401 API Key 无效，或没有所选模型的访问权限`，说明 Worker 已成功连接上游服务商，此前 502 出站网络问题在线上未复现；未使用真实密钥，也未产生模型费用。
- `POST /api/ai/assistant` 返回 `404`，说明本次新增接口尚未部署到 `sci.luzen.org`。
- 因此本交付**没有**声称生产环境已完成升级；需要按上述步骤重新部署 Worker。
