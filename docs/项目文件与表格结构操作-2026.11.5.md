# 项目文件与表格结构操作（v1.1.0）

日期：2026-11-05　分支：`feature/v1.1.0`　版本：v1.1.0

范围：`electron/`、`src/services/desktop-project-2026.11.4.ts`、`src/state/`、`src/components/Worksheet-*`、四个分析页

本轮把桌面端从「浏览器式自动保存」升级为 Origin 式的**项目文件工作方式**，并把行列插入 / 删除、右键菜单补齐到工作表。

---

## 1. 项目文件（`.plab`）

### 1.1 文件格式

`.plab` 仍是完整的工作区快照，旧的 `downloadJson` 备份文件继续可读：

```json
{
  "format": "perovskite-lab-project",
  "version": 1,
  "appVersion": "1.1.0",
  "savedAt": "2026-11-05T12:00:00.000Z",
  "workspace": { "...": "完整 Workspace（原始数据、所有 Sheet、绘图设置、分析结果、列元数据）" }
}
```

### 1.2 生命周期（主进程持有路径）

| 动作 | IPC | 行为 |
| --- | --- | --- |
| 保存 | `project:save` | 已有路径直接写入；没有路径时弹出系统「另存为」窗口，默认文件名 `Perovskite Lab YYYY.M.D.plab` |
| 另存为 | `project:save` (`saveAs: true`) | 总是弹窗，写到新文件，原文件保持不动 |
| 打开 | `project:open` | **只读取内容**，不修改当前项目路径 |
| 确认切换 | `project:adopt` | 渲染进程解析 + 用户确认后才调用，此刻 `projectPath` 才更新 |
| 新建 | `project:new` | 清空路径，下一次保存重新选位置 |
| 未保存状态 | `project:set-dirty` | 只影响标题与关闭确认 |
| 未保存提醒 | `project:confirm-unsaved` | 原生三按钮：保存 / 不保存 / 取消 |

要点：

- **路径不会被提前改写**：旧实现 `readProjectFile()` 会先 `projectPath = filePath` 再返回内容，导致文件损坏或用户取消时窗口标题 / 下次保存目标已经变成新文件。现在读取与采纳分离。
- **安全写入**：`electron/project-files-2026.11.5.ts` 的 `writeFileAtomic()` 先写同目录临时文件并 `fsync`，再 `rename` 覆盖；写入中断最多留下 `.tmp`，原文件不会被截断。
- **窗口标题**：`*项目名 — Perovskite Lab vX.Y.Z`，未命名项目显示 `未命名项目`；页面 `<title>` 不再覆盖窗口标题。
- **关闭确认**：有未保存修改时关闭窗口会询问保存 / 不保存 / 取消；选择保存会等渲染进程真正写盘后再关闭。
- **启动恢复**：命令行 / Finder 显式传入 `.plab` 时只加载该文件，绝不使用上次的工作区；未指定文件时才恢复上次项目（优先使用本地草稿，并标记未保存）。

### 1.3 草稿与正式文件分离

自动保存不再写死一个键，而是按「项目身份」分键：

| 场景 | 键 |
| --- | --- |
| 浏览器 | `perovskite-lab-workspace-v1`（沿用旧键，旧数据无损） |
| 桌面端未落盘项目 | `perovskite-lab-draft-v1:untitled` |
| 桌面端已保存项目 | `perovskite-lab-draft-v1:file:<绝对路径>` |

- 旧版桌面端把工作区存在 `perovskite-lab-workspace-v1`：升级后首次启动会接管这份数据（旧键保持不动），并标记为未保存，提醒用户另存为项目文件。
- 只有存在未保存修改时才写草稿；保存成功后立即清掉该身份的草稿，并作废尚未触发的草稿写入。
- 打开项目文件（对话框 / 双击 / 上次项目）时以文件内容为准，对应身份的草稿会被丢弃，因此 A 的草稿永远不会被 B 覆盖或显示。
- 项目文件损坏时：不加载、不覆盖当前工作区、不改变当前路径，只在界面提示原因。

## 2. 表格行列结构操作

### 2.1 通用 API

`Worksheet` 新增两个属性，把结构操作交给页面自己的数据模型处理：

```ts
onStructure?: (action: WorksheetStructureAction) => void;
canStructure?: (action: WorksheetStructureAction) => string | null; // 返回禁用原因
```

```ts
type WorksheetStructureAction =
  | { type: 'insert-row'; index: number; count: number }   // 在 index 之前插入
  | { type: 'append-row'; count: number }
  | { type: 'delete-row'; index: number; count: number }
  | { type: 'insert-column'; index: number; count: number }
  | { type: 'append-column'; count: number }
  | { type: 'delete-column'; index: number; count: number };
```

纯函数在 `src/domain/worksheet-structure-2026.11.5.ts`（数量归一化、网格增删、删除确认阈值、索引重映射），页面只负责写回自己的字段。

### 2.2 各页面的行为

| 页面 | 行 | 列 |
| --- | --- | --- |
| 光谱工作台（原始表） | 插入 / 追加 / 删除，`mapping.start` 随表头移动 | 插入 / 追加 / 删除；同步平移波长列 `x`、强度列 `ys`、`meta`、列头元数据（`sheetMetadata`）与列→光谱映射（`rawColumnSpectra`）；删除强度列会移除对应光谱 |
| 对象筛选 | 插入 / 追加 / 删除对象行，删除空白参考时清空 `blankId` | 固定列，禁用并提示原因 |
| 校准与检出限 | 插入 / 追加 / 删除校准点 | 固定列，禁用并提示原因 |
| 浓度梯度 | 插入 / 追加 / 删除目标浓度行（空行保留） | 公式列，禁用并提示原因 |
| 多探针识别分析 | 插入 / 追加 / 删除实验行 | 探针列可插入 / 删除（右键列标「插入列 / 删除列」或页面「添加探针」），同时更新 `probes` 与每行 / 每批的 `values`；样本 ID、离子种类、平行编号与「删除行」操作列受保护 |

- 删除是真正的结构删除，不会退化成「清空单元格」。
- Delete 键清空单元格的原有行为保持不变。
- 固定字段、必需列、只读计算结果通过 `canStructure` 返回中文原因，菜单项直接显示原因并禁用。
- 结构改变后图表与拟合由派生状态重新计算，不会残留旧结果。

### 2.3 撤销 / 重做

`src/state/useSheetHistory-2026.11.5.ts` 提供整表历史（按 sheet 分栈，最多 40 条，不写入项目文件）：

- 单元格编辑、粘贴、清空与行 / 列结构修改共用同一条历史；
- 一次批量插入或删除只产生一条记录（例如「在上方插入 3 行」）；
- 工具栏「撤销 / 重做」与 `⌘Z` / `Ctrl+Z` 走同一条历史。

### 2.4 右键菜单

- 桌面端（`window.desktopProject` 存在）把工具栏的插入 / 新增入口迁到右键菜单；浏览器端保留原有按钮，同时也能使用右键菜单。
- 右键行号只显示行操作，右键列标只显示列操作，右键数据单元格显示两者。
- 菜单项：复制、粘贴、插入行（上方 / 下方 / 末尾）、插入列（左侧 / 右侧 / 末尾）、删除行、删除列。
- 右键落在当前选区内保留选区（整行 / 整列选区才批量生效），落在选区外先更新选中目标。
- 批量删除超过 20 行、4 列或删除区域内已有 50 个以上非空单元格时，弹出确认提示。
- 点击其他位置、按 Esc、窗口失焦或缩放都会关闭菜单；菜单按视口边缘夹紧，子菜单在右侧空间不足时向左展开。
- 不改动拖拽框选、复制粘贴与键盘导航。
- 工具栏「插入行 / 插入列」在选区落在受保护列（例如多探针表的必需列）时自动退回到末尾追加，不会变成一个只报错的按钮；子菜单不受外层菜单裁剪，靠近屏幕边缘时自动向左展开。

桌面端验收覆盖：

1. 录入数据 → 保存 `A.plab`（真实文件 + 标题去掉 `*`）。
2. 修改后另存为 `B.plab`，A 的内容不变。
3. `⌘S` 只更新当前文件 B。
4. 有未保存修改时打开 A：取消 → 停留在 B 且数据不变。
5. 选择不保存 → 加载 A 的实际内容，B 文件不被覆盖。
6. 打开损坏文件 → 保持当前项目与数据。
7. 双击 A / B 启动 → 分别显示各自的内容，不会用上次恢复的工作区顶替。
